# НПС Гельзенкирхена — предложения (2026-10-09)

Основа — данные игры `Maangof/pfeffi-game`, ветка `claude/meshy-subscription-features-ctk73a` (в `main` этого пока нет):
`docs/CONCEPT_QUARANTINE.md` (лор «Карантин», §4а «Поле у зданий»), `docs/DECISIONS.md` 2026-10-09
(«Оставшиеся» за стеклом, шлюзы), `tools/build_city.gd` (`_airlock`, `_kiosk_hatch`, `_shop_room`, `_resident`),
`scenes/club/ClubWorker.gd`, `data/economy/*.tres`, сюжет «Три слуха».

## 0. Новая идея и что она меняет

**Было (решение 2026-10-09):** жителей-НПС на улицах нет. За стеклом стоит неподвижный силуэт из двух коробок
(`_resident`), без логики и без сети.

**Предлагается:** НПС **анимированные и прорисованные**, но почти все остаются **внутри зданий, за защитным полем
и стеклом**. Само решение не отменяется: на улицах НПС по-прежнему нет, просто силуэт за стеклом становится живым
человеком.

Технически это тот же путь, что и у `ClubWorker`:
- **Только вид.** У каждого клиента своя копия, по сети ничего не передаётся. Торговлю, как и сейчас, ведут
  `ShopCounter`, `CourierDesk` и `FundbueroCounter`. Сетевая нагрузка не растёт, а это и был главный довод автора.
- **Поведение — короткий набор клипов** без ИИ: `idle`, затем 2–4 «занятия» в случайном порядке (протирает
  стойку, режет мясо, курит, листает телефон). Когда игрок подходит к окошку (проверяется локально, по дистанции),
  НПС играет `greet`, при покупке — `serve`. Поворот головы к игроку — `LookAtModifier3D` (Godot 4.x), тоже локально.
- **Поле — главный художественный ход.** Сквозь дым и мерцание поля (`fog_field.gdshader`) жителей видно
  обрывками: движение, свет лампы, силуэт у окна. Чётко их видно только в шлюзе у окошка. Поэтому дальние НПС могут
  быть дешёвыми (LOD, 12–15 к/с), а детализация нужна только у окошка.
- **Бюджет.** Одновременно видно 6–10 НПС (поле гаснет на 130 м). Один НПС — 15–25 тыс. треугольников (LOD0
  у окна), 3–5 тыс. на расстоянии, одна общая скелетная схема Mixamo (как у героини, 65 костей без пальцев
  на LOD1).

## 4. Три уровня качества — на выбор

| Вариант | Что это | Плюсы | Минусы |
|---|---|---|---|
| **A. «Живые силуэты»** | 1 базовая модель низкой детализации + смена цвета, 2–3 клипа, видны только сквозь поле | день-два, почти бесплатно для GPU | вблизи у окошка выглядит бедно |
| **B. «Лицевые + фон» (рекомендую)** | 6 прорисованных лицевых НПС из §3 (уровень Валентины, но облегчённые до ≈25 тыс. треугольников) + модульные жители из §1 и ликвидаторы из §2 на одном скелете | вблизи качественно, вдали дёшево; одна схема клипов | нужен свой набор клипов «работы» (Mixamo: bartending, cutting, counting money, smoking, leaning on window) |
| **C. «Полная сцена»** | B + мини-сценки по времени суток (Ночная смена: свет гаснет, Мехмет закрывает ставни, ликвидаторы меняют смену) и реакция на прилив (жители отходят от окон) | город ощущается живым, хорошо подаёт загадку поля | больше клипов и логики расписания (только локально) |

Порядок работы (вариант B):
1. Валентина = эталон пайплайна. Исправить находки из §5 → `club_worker.glb`.
2. Мехмет (3.1) и Фрау Козловски (3.3) — первые лицевые НПС: дёнер и киоск видны чаще всего.
3. Общий скрипт `ShopWorker` (обобщение `ClubWorker`): модель, список клипов, `greet` / `serve` по сигналу
   прилавка, `LookAt`. Вместо `_resident` из `build_city` — точка-маркер для `ShopWorker`.
4. Модульный житель для окон, затем ликвидаторы за полем.

## 5. Проверка модели в Blender

**Чего нет:** файла `assets/characters/club_worker.glb` нет ни в одной ветке `pfeffi-game` и в `pfeffi-mature`.
По `DECISIONS.md` он лежит на ПК автора («с ПК, скелет проверяет сессия на ПК»). Поэтому проверена единственная
готовая женская модель проекта — **Валентина** (`assets/characters/standin_valentina/valentina_standin.glb`,
источник — `…/seductress/valentina_stand.blend`). Скорее всего, работница клуба экспортирована из неё же.

Чем проверял: Blender 5.2.2 (модуль `bpy`), рендер Cycles. Снимки — `check/`, скрипт — `check/check_model.py`
(`python check_model.py <файл.glb> <папка>`), сводка — `check/report.json`.

| Что | Результат | Оценка |
|---|---|---|
| Скелет | `Armature`, 97 костей `mixamorig:*` | ✅ совместим с клипами Mixamo |
| Клипы | 13: idle, walk, run, crouch_*, jump, attack_*, *_torch | ✅ для героини; ❌ для работника нет «рабочих» клипов (протирать стойку, наливать) |
| Рост в idle | **1,62 м** | ⚠ `ClubWorker.HEIGHT_M = 1.78`, модель растянется в 1,1 раза |
| Лишний объект | **`Icosphere` 1,9 × 2 × 2 м** в корне glb, виден при рендере | ❌ `ClubWorker._fit` считает габарит по всем мешам, получит 2,6 м и **уменьшит работницу до ≈1,1 м**. Удалить при экспорте (в `city_walk.py:1204` это уже делается, в `export_hero.py` — нет) |
| Треугольники | **176 тыс.** (тело 107 тыс., зубы 28 тыс., волосы 16 тыс.) | ⚠ много для НПС; для работника — децимация тела до ≈20–25 тыс., зубы до 2 тыс. |
| Текстуры | кожа 4096², платье 2094×2950 (не степень двойки), волосы 2048² | ⚠ для НПС 2048² достаточно; платье привести к 2048² |
| Одежда | грудь тела **проступает сквозь платье** (видно на `front.png` / `three_quarter.png`), разрезы платья на бёдрах | ❌ для базовой 16+ сборки — исправить (сжать тело под платьем или маска-удаление скрытых граней) |
| Обувь | нет, сетчатые чулки до стопы | ⚠ для работницы за стойкой — добавить обувь |
| Лицо, волосы, глаза | хорошее качество (`face.png`), карточки волос без артефактов | ✅ |

Снимки: `check/contact_sheet.png` (спереди, 3/4, сбоку, сзади, глина), `check/face.png`.
Файл `.blend` для открытия в Blender собирается тем же скриптом (`model_check.blend`, 57 МБ — в git не кладётся).
